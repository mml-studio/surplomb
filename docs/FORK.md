# Surplomb as a fork of God's Eye View

This page is for the maintainers of
[God's Eye View](https://github.com/bilawalsidhu/gods-eye-view), who know that
codebase and not this one. Surplomb (`mml-studio/surplomb`) is a fork that puts
French public data on the same globe: 60 registered layers, 44 of which do not
exist upstream. It keeps the MIT license, with both copyright lines in
[LICENSE](../LICENSE).

Every number below was measured on 2026-09-19 against `upstream/main` at
`0d41b6be` (2026-09-16) and this repository's `main` at `62d1000e` (#273).
A bare `#N` is a pull request in this repository; `upstream #N` is one in
`bilawalsidhu/gods-eye-view`.

## 1. Fork point and drift

- **Fork point: `880a672b`**, "Release God's Eye View as open source"
  (2026-08-24). It is still the merge base, because this fork has never merged
  upstream. Upstream work came in rewritten instead: #56 re-expressed
  upstream #83 (`node:fs` out of browser modules), #45 (the GBFS byte cap,
  applied here to all six response caps that counted characters) and #93 (the
  FIRMS `fires.push` spread); #125 took three fixes to Overpass handling and
  military installations, Provider Settings, the Pinokio installer,
  `npm run doctor` and the CI workflow.
- **Ahead: 268 commits**, each the squash merge of one pull request (#3 to
  #273). **Behind: 416 commits**, 290 of them non-merge.
- Since the fork point this side changed 1,411 files (+631,087 / −11,310
  lines) and upstream 1,148 files (+302,237 / −82,138). A trial merge conflicts
  on **133 files**, 52 under `src/data/`, including `vite.config.js`,
  `src/main.js`, `src/ui.js`, `src/data/manager.js`, `src/data/layerState.js`,
  `index.html` and `style.css`.

```bash
git fetch upstream main
git merge-base origin/main upstream/main
git rev-list --count upstream/main..origin/main   # ahead
git rev-list --count origin/main..upstream/main   # behind
git merge-tree --write-tree --name-only origin/main upstream/main | sed -n '2,/^$/p' | grep -c .
```

`.github/workflows/upstream-watch.yml` was meant to report this weekly; both of
its runs (2026-09-07, 2026-09-14) failed, so the drift is measured by hand.

## 2. Architecture

Upstream split the application into components after the fork point: 62 of
the 128 PRs it merged between 2026-09-11 and 2026-09-16 are refactors or
extractions (upstream #227, #311, #319, #320 and the `refactor:` series after
them). This fork kept the release layout and grew it in place.

| Concern | Upstream `0d41b6be` | Surplomb |
|---|---|---|

### Layer registry

Both sides still have `src/data/layerState.js` (share-link tokens and state
dispositions): 21 ids upstream, 60 here, a count `layerState.test.mjs` locks.
16 ids are shared, 44 exist only here, 5 only upstream (`alpr-cameras`,
`directions`, `transit`, `bhote-koshi-2026`, `bhote-koshi-locator`). Where
upstream builds its catalog through `application/catalog` and
`src/standalone/catalog.js`, three files do it here:

- `src/data/layerManifest.js`, generated by `npm run layers:manifest` from
  `scripts/lib/layerManifestSources.mjs`: each layer's name, source,
  capabilities, default parameters and a `load()` import. `src/main.js`
  registers a `createLazyLayer` stub per entry, so layer modules arrive on the
  first toggle, not at boot (#123, 483 kB off the entry). `layerManifest.test.mjs`
  re-derives every field on each `npm test`.
- `src/data/layerTaxonomy.js`: seven panel groups, each row's French label, and
  `coverage` (`global`, `fr`, `cities`). It is validated against the registry at
  import, so an ungrouped layer fails at boot (#17).
- `src/data/layerFusions.js`: layers that show the same subject share one panel
  row (#128).

`military-awareness` is registered but hidden, so the panel counts 59 layers.

### Language

French is the default locale and English the second. Upstream is English-only
(`<html lang="en">`, no i18n module).

- Today: `index.html` and `fiche.html` declare `lang="fr"`. Strings written in
  this fork are French in place; the shell inherited from upstream is still
  English (`DATA LAYERS`, `MAP SOURCE`, `POWER UP`, `Provider Settings`), so the
  globe is mixed. 156 lines in 60 runtime modules hard-code `'fr-FR'`.
- Arriving now: a `<module>.i18n.js` catalog beside each module, French and
  English side by side as `{ fr, en }` (the rule is in [AGENTS.md](../AGENTS.md)
  since #272); shared formatters in `src/i18n/`; switching language saves the
  choice and reloads, and the share hash restores camera, layers and panels.
  Data values (municipality names, DVF property types) are never translated.
  [GLOSSARY.md](GLOSSARY.md) fixes the English for French terms.

## 3. Upstream's docs, mapped onto this fork

None of the four has a counterpart here: the structures they describe were
written after the fork point. Where the same concern lives:

**[`docs/APPLICATION.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/main/docs/APPLICATION.md)**
(`createApplication`, constructors, `defer`/`signal` ownership)
- No application export and no teardown. `src/boot.js` imports `src/main.js`,
  which constructs the viewer, `StyleManager` (`src/ui.js`),
  `DataLayerManager` (`src/data/manager.js`) and the layer stubs at module scope.
- Geospatial services: `src/locations.js` calls `/api/geocode`, served by
  `keylessGeocodeProxy()` in `vite.config.js` (IGN Géoplateforme; #16).
- Voice: `src/voice/` (`lazyVoice.js` loads it on first use, `gevRealtime.js`,
  `gevActions.js`); `/api/realtime/token` and `/api/voice/*` are in
  `vite.config.js`; the key is OpenAI or OpenRouter (#111).

**[`docs/CODE-BOUNDARIES.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/main/docs/CODE-BOUNDARIES.md)**
(Prettier scope, component owners, `npm run check:boundaries`, package exports)
- No formatter and no package exports; style is by convention
  ([CONTRIBUTING.md](../CONTRIBUTING.md#coding-style)).
- Boundaries are unit tests: `src/browserModuleBoundary.test.mjs` fails when a
  browser-built module imports `node:*` (three server-only modules under `src/`
  are exempt, and the exemption is re-checked on every run);
  `src/deliveryPolicy.test.mjs` pins the cache and compression rules.
  `npm run perf:graph` reads the entry chunk from Rollup's module graph.
- Server providers: `vite.config.js` (section 2). Layer owners: `src/data/<layer>.js`.

**[`docs/INFRASTRUCTURE-LAYERS.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/main/docs/INFRASTRUCTURE-LAYERS.md)**
(`createInfrastructureLayers` for datacenters and dams)
- `src/data/localGeojson.js` (2,787 lines, 892 at the fork point) is still the
  one `createLocalGeoJsonLayer` factory, used by `src/data/localLayers.js` for
  four packs (datacenters, dams, ports, airports) and by `src/data/datasetLayer.js`
  for plugged datasets (#113).
- The packs differ: dams hold 6,840 features here (704 upstream), France
  re-extracted from OpenStreetMap (#29, #41, #182); datacenters hold 4,638
  (4,351 upstream), with DCWatch power figures for French sites (#197).

**[`docs/MAINTAINER_WORKFLOW.md`](https://github.com/bilawalsidhu/gods-eye-view/blob/main/docs/MAINTAINER_WORKFLOW.md)**
(acceptance gates for community PRs)
- One owner opens and merges every PR (269 merged, all from `mml-studio`).
  259 of the 268 commits carry a `Co-Authored-By: Claude` trailer: the code is
  written with coding agents and reviewed by the owner.
- Gates: [AGENTS.md](../AGENTS.md) ("Before you push"), the
  [PR template](../.github/pull_request_template.md) (What changes / Why /
  Verified), and CI: `.github/workflows/ci.yml` (`npm run doctor`, `npm test`,
  `npm run build` on Node 24.14.0 and 26.x, the Pinokio install on Windows) and
  `.github/workflows/english.yml` (#273).
- Browser checks: 134 `scripts/qa-*.mjs` harnesses (64 upstream) and
  `npm run test:track`. None runs in CI.

## 4. What is French, and what could go upstream

### France-specific: stays here

**Why France:** the layer count follows from what the French State publishes,
and France ranks first on both the OECD and the EU open-data indexes: 0.96 out
of 1 in the OECD OURdata Index 2025, ahead of Korea (0.95), against an OECD
average of 0.53
([OECD, February 2026](https://www.oecd.org/content/dam/oecd/en/publications/reports/2026/02/digital-government-index-and-open-useful-and-re-usable-data-index_dbe102ed/6347ec74-en.pdf)),
and first of 36 European countries at 100% in the EU Open Data Maturity 2025
assessment, for the fifth consecutive year
([data.europa.eu](https://data.europa.eu/en/open-data-maturity/2025)).

- **40 layers on French sources**: 38 with `coverage: 'fr'`, plus two city
  layers (`idfm-network`, `velo-pulse-fr`). By domain, with the PR that
  introduced each:
  - Energy: `france-energy` (#9), `gas-fr` (#11), `edf-power-plants` (#12),
    `rte-generation` (#14), `fr-hydro-plants` (#18), `irve-fr` (#27).
  - Ground mobility: `transit-fr` (#6), `shared-mobility-fr` (#8),
    `road-status-fr` (#25), `road-events-fr` (#26), `idfm-network` (#36),
    `comptages-fr` (#53), `velo-pulse-fr` (#62).
  - Buildings, land and housing: `bdtopo-buildings` (#19), `dvf-sales`,
    `dpe-fr`, `urbanisme-gpu` (#36), `cadastre-fr` (#46), `sitadel-fr`,
    `amenities-fr` (#53), `ads-fr` (#58), `filosofi-fr`, `isochrone-fr`,
    `implantation-fr` (#62), `avis-valeur` (#101), `comparables-fr` (#105).
  - Public services: `schools-fr` (#30), `sup-fr` (#42), `petite-enfance-fr`
    (#44), `medecins-fr` (#48), `delinquance-fr` (#53).
  - Risks and environment: `vigicrues`, `hubeau-hydro`, `meteofrance-vigilance`
    (#7), `georisques` (#36), `meteo-stations-fr` (#51), `bruit-fr`,
    `fraicheur-fr` (#53), `gironde-megafire-2026` (#134).
  - Networks and sensors: `anfr-fr` (#53).
- **The French public-data stack** behind them, each license in
  [DATA_SOURCES.md](../DATA_SOURCES.md): IGN Géoplateforme (basemaps, geocoder,
  BD TOPO, cadastre, isochrones), Etalab (DVF, dated cadastre), the national
  address database (BAN) and building register (RNB), ADEME (DPE), Géorisques,
  Géoportail de l'urbanisme, SDES Sitadel, INSEE (Filosofi 200 m grid, census),
  transport.data.gouv.fr (GTFS, GTFS-RT, GBFS), Bison Futé, ODRÉ, RTE, EDF,
  Météo-France, Vigicrues, Hub'Eau, ANFR, and the education and health registers.
- **France-only helpers**: `src/data/franceDepartements.js` (point-in-department
  over bundled IGN outlines, mainland only; #30), `src/data/communeCode.js`
  (#100), `scripts/lib/lambert93.mjs` (#25), `src/data/ignBilTerrain.js` (#16).
- **The hosted product**: the landing page (`src/vitrine/`, #257; `/` and
  `/globe` since #259), the Address X-ray `fiche.html` (#100), the hosted trial
  (`src/trialQuota.js`, #245), the first-run A/B test (`src/firstRunAb.js`,
  #254), the French legal pages (#246), the chronicle, a server-side archive of
  live feeds (`src/data/chronicle.js`, #95), and `deploy/`.

here therefore goes as one defect per PR, branched from `upstream/main`, in

## 5. Ten files to read first

1. [`docs/CURRENT-STATE.md`](CURRENT-STATE.md): the runtime reference, one section per layer and subsystem; search it rather than read it (4,724 lines).
2. [`AGENTS.md`](../AGENTS.md): the working rules on one page (language, commits, what to run before pushing).
3. `src/boot.js`: the page entry; the landing page at `/`, the globe at `/globe`, Cesium only for the globe.
4. `src/main.js`: what upstream's four constructors do, in one module.
5. `src/data/layerManifest.js`: all 60 layers in one generated file, with their lazy `load()`.
6. `src/data/layerTaxonomy.js`: the seven panel groups and each layer's `coverage`.
7. `src/data/manager.js`: the release-era lifecycle class, now 4,362 lines; upstream #495 split its two roles.
8. `vite.config.js` from line 28,440: the `plugins` array indexes the server; each entry names the proxy to read.
9. `src/data/dvfSales.js` with `src/data/dvfFeed.js`: the pattern the French layers follow; browser layer, pure parser, and `dvfProxy()` (`vite.config.js`, line 23,582) between them.
10. [`DATA_SOURCES.md`](../DATA_SOURCES.md): license and attribution for every source, including the share-alike and non-commercial ones.

## 6. History

  mostly in French. They were deliberately not rewritten: no force-push, and
